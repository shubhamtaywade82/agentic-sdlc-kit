# fixture-rails-api

A minimal but real Rails 8 API-only application with a passing RSpec suite.
**The third reference fixture for the Agentic SDLC Kit**, and the first
that exercises the `ruby-rails` stack pack end to end against a real
`bundle exec rails db:prepare && bundle exec rspec` run.

## Why this fixture exists

`fixture-ruby-rspec` proved the verification classifier recognizes RSpec
output against a plain-Ruby project. This fixture proves the same against
a **Rails** application — the `ruby-rails` stack pack's default command
(`bundle exec rspec`) running inside a booted Rails environment with
Active Record, a migration, and `maintain_test_schema!`. It closes the
last declared gap for the Ruby/Rails stacks: the kit now drives a real
Rails TDD cycle, not just a plain-Ruby one.

## Running the fixture (standalone)

```bash
cd fixtures/fixture-rails-api
bundle install
bin/rails db:prepare          # creates storage/test.sqlite3, loads schema.rb
bundle exec rspec             # runs the 2 examples
```

The fixture has three gem dependencies (`rails`, `sqlite3`, `rspec-rails`)
and a single sqlite database, so the suite boots in seconds with no
external services.

## What the kit does with this fixture

- **M2 `kit inspect`**: scans the fixture read-only, detects the
  `ruby-rails` stack (Rails gem + `app/` layout + `bin/rails`), and
  produces a `ProjectProfile` whose test command is `bundle exec rspec`.
- **Feature workflow / Tier C conformance**: a feature run drives the TDD
  phase cycle; the task's verification command is `bundle exec rspec`. The
  evidence gate classifies a failing RSpec run as `assertion` (Red) and a
  passing run as `Green` — proven in CI by the `fixture-rails` lane.

## Lean-railtie note

`config/application.rb` requires only `active_model`, `active_record`,
`action_controller`, and `action_view` railties. The heavier frameworks
(`active_storage`, `action_cable`, `action_mailer`, `action_mailbox`,
`action_text`, `active_job`, `rails/test_unit`) are intentionally not
loaded, so the fixture needs no `config/storage.yml`, action-cable config,
or mailer config and boots against a single sqlite database. A real
application generated by `rails new --api` loads `rails/all`; this fixture
is leaner to keep the CI lane fast and the surface auditable.
